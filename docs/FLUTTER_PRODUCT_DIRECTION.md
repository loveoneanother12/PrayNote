# PrayNote Flutter 제품 방향

## 개발 환경

- Flutter stable 3.47.4 / Dart 3.13.3
- Android Studio + Android 16(API 36) 에뮬레이터
- Xcode 26.6 + iOS 26.5 iPhone/iPad Simulator
- CocoaPods 1.17.0

## 앱 구조 원칙

- 상태 관리: Riverpod
  - 인증, 사용자 설정, 그룹, 기도제목, 챌린지를 기능 단위 Provider로 분리한다.
  - 서버 상태와 화면 임시 상태를 분리하고 낙관적 업데이트를 사용한다.
- 라우팅: go_router
  - 인증 전/후 라우트, 초대 링크와 푸시 알림 딥링크, 관리자 접근 제어를 선언적으로 구성한다.
  - 모바일 하단 탭은 StatefulShellRoute로 탭별 탐색 상태를 보존한다.
- 애니메이션: flutter_animate
  - 완료, 저장, 챌린지 달성처럼 의미 있는 피드백에만 짧게 사용한다.
  - 화면 전환을 지연시키거나 과도한 장식이 되는 애니메이션은 피한다.
- 플랫폼 적응
  - 공통 정보 구조는 유지하되 iOS와 Android의 뒤로가기, 공유, 알림 권한, 바텀시트 관습을 따른다.
  - 휴대폰은 하단 내비게이션, 태블릿은 NavigationRail과 2열 상세 구조를 기본으로 한다.

## 최상위 UI 패턴 5개

### 1. 오늘 할 일에 집중하는 홈

- 참고: Mobbin의 Headspace/Fabulous 홈 패턴
- 적용: 첫 화면에는 오늘의 기도, 이어서 기도할 항목, 진행 중 챌린지만 우선 노출한다.
- 방식: 큰 핵심 카드 1개 + 작은 후속 카드로 정보 위계를 만들고 긴 전체 피드는 별도 진입으로 둔다.
- 참고 링크: https://mobbin.collaboo.co/explore/screens/cda46030-4c2b-4b7c-b6f1-6e08db0ddf96
- 참고 링크: https://mobbin.collaboo.co/explore/screens/2e2781a1-8954-45b7-8074-fd9ed411db72

### 2. 기록을 방해하지 않는 빠른 작성과 타임라인

- 참고: App Store Editors' Choice인 Day One
- 적용: 작성 버튼을 누르면 한 문장부터 바로 저장할 수 있고, 그룹/개인 공개 범위는 같은 흐름 안에서 선택한다.
- 방식: 날짜가 명확한 카드, 달력 점 표시, 검색/필터, 해결된 기도 회고를 하나의 기록 구조로 통일한다.
- 참고 링크: https://apps.apple.com/us/app/day-one-daily-journal-diary/id1044867788

### 3. 비교보다 함께 완주하는 그룹 챌린지

- 참고: Nike Run Club의 기간·진행률·친구 챌린지 구조와 PrayerX의 공동 기도 흐름
- 적용: 순위 경쟁보다 `매일 한 명 이상 기도`와 `기간 동안 0회 참여자가 없기`를 공동 성공 조건으로 보여준다.
- 방식: 남은 기간, 오늘 달성 여부, 참여자별 부담 없는 상태, 그룹 공동 진행 바를 한 화면에서 파악하게 한다.
- 참고 링크: https://apps.apple.com/us/app/nike-run-club-running-coach/id387771637
- 참고 링크: https://www.behance.net/gallery/75545803/UIUXInteraction-Design-for-Social-Praying-Mobile-App

### 4. 죄책감 없이 지속을 돕는 연속 기록

- 참고: Apple의 streak 피처와 Finch의 가벼운 일일 체크인
- 적용: 연속 기도일, 역대 최장 기록, 다음 이정표를 짧게 보여주되 끊겼을 때 실패 문구나 붉은 경고를 사용하지 않는다.
- 방식: 오늘 한 번의 기도 완료를 즉시 축하하고 7·14·30·50·100일 같은 이정표는 점진적으로 공개한다.
- 참고 링크: https://apps.apple.com/us/iphone/story/id1713628724
- 참고 링크: https://apps.apple.com/us/app/finch-self-care-pet/id1528595748

### 5. 차분하고 신뢰감 있는 공동체 피드

- 참고: Dribbble의 Altar, Behance의 Tazkirah
- 적용: 작성자 색, 그룹명, 작성일, 기도 완료 반응을 절제된 카드에 배치하고 민감한 내용의 공개 범위를 항상 확인 가능하게 한다.
- 방식: 낮은 채도의 배경, 충분한 여백, 명확한 제목/본문 대비를 사용하며 글래스모피즘은 핵심 CTA를 흐리지 않는 범위에서만 쓴다.
- 참고 링크: https://dribbble.com/shots/27030693-Altar-Spiritual-Community-Prayer-Request-Mobile-App-UI
- 참고 링크: https://www.behance.net/gallery/247081501/Tazkirah-Prayer-Tracker-Quran-App-UIUX-Design

## 추가 App Store 미감 레퍼런스

### Things 3 — 조용하지만 빠른 도구

- 화면 장식을 줄이고 콘텐츠와 다음 행동을 가장 먼저 보이게 한다.
- 핵심 작성 버튼은 항상 같은 위치에 두고, 드래그와 단계적 공개로 복잡한 기능을 평소에는 숨긴다.
- PrayNote 적용: 작성 버튼의 위치와 동작을 전 화면에서 통일하고 카드 내부 보조 기능은 더보기로 정리한다.
- 참고 링크: https://apps.apple.com/us/app/things-3-for-ipad/id904244226

### Structured — 한눈에 읽히는 시각적 구조

- 색과 시간축을 정보 구분에 사용해 많은 항목도 빠르게 훑을 수 있게 한다.
- 사용자가 색과 아이콘을 조정할 수 있지만 기본 화면은 단순하게 유지한다.
- PrayNote 적용: 달력, 기도 기록, 챌린지를 하나의 시각 언어로 묶고 색만으로 상태를 전달하지 않는다.
- 참고 링크: https://apps.apple.com/us/app/structured-daily-planner-todo/id1499198946

### stoic. — 부담 없는 안내형 기록

- 짧은 질문과 차분한 화면으로 사용자가 기록을 시작할 때 느끼는 부담을 낮춘다.
- 강제적인 루틴보다 유연한 개인화와 정돈된 회고 경험을 제공한다.
- PrayNote 적용: 빈 화면과 작성 화면에 짧은 안내 문구를 사용하고 연속 기록이 끊겼을 때 실패감을 주지 않는다.
- 참고 링크: https://apps.apple.com/us/app/stoic-journal-mental-health/id1312926037

### Gentler Streak — 다정한 진행 시각화

- 성과를 보여주되 휴식과 개인 상태를 존중하는 문구와 그래픽을 사용한다.
- 복잡한 기록도 부드러운 차트와 적은 수의 지표로 이해하게 한다.
- PrayNote 적용: 연속 기도일과 목표를 경쟁 수치가 아닌 지속을 격려하는 리듬으로 표현한다.
- 참고 링크: https://apps.apple.com/us/app/gentler-streak-workout-tracker/id1576857102

### Bear — 타이포그래피 중심의 집중 경험

- 편집 도구보다 글 자체가 먼저 보이며, 명확한 글자 위계와 제한된 색으로 집중을 돕는다.
- 기능은 깊지만 작성 중에는 필요한 도구만 노출한다.
- PrayNote 적용: 기도제목 본문을 카드의 주인공으로 만들고 작성자·그룹·날짜는 한 단계 낮은 위계로 정리한다.
- 참고 링크: https://apps.apple.com/us/app/bear-markdown-notes/id1016366447

### Apple Design Awards에서 확인한 공통 방향

- Moonlitt처럼 첫 사용 흐름은 짧고 플랫폼 관습에 맞아야 한다.

## PrayNote UI 개선 백로그

### P0 — 먼저 통일할 기반

1. **타이포그래피 체계**: 대제목 28, 화면 제목 22, 섹션 제목 17, 본문 15, 보조 정보 13을 기준으로 삼고 굵기는 400·500·600 세 단계로 제한한다. 모든 제목을 과하게 굵게 쓰지 않는다.
2. **카드 사용 절제**: 모든 영역을 카드로 감싸지 않고, 실제 개체와 핵심 행동에만 카드를 사용한다. 나머지는 여백, 배경 톤, 얇은 구분선으로 묶는다.
3. **홈의 한 가지 주행동**: 첫 화면에 `오늘 기도하기`를 가장 크게 두고, 이어서 기도할 항목·진행 중 챌린지·연속 기록은 짧은 모듈로 압축한다.
4. **기도제목 카드 재정리**: 본문을 가장 크게, 작성자 색·그룹·날짜·공개 범위는 보조 정보로 둔다. `기도했어요`만 주행동으로 두고 수정·공유·해결은 작성자용 더보기에 모은다.
5. **작성 흐름 단축**: 작성 버튼을 누르면 즉시 본문 입력에 초점을 주고, 개인/그룹 및 공유 대상은 접을 수 있는 컨텍스트 선택기로 둔다. 작은 화면에서는 전체 높이 시트를 사용한다.

### P1 — 핵심 화면 재구성

1. **마이**: 연속 기도일, 역대 기록, 달력, 해결된 기도를 하나의 `기도 리듬`으로 연결하고 단순 숫자 카드의 반복을 줄인다.
2. **그룹**: 그룹 카드에 현재 챌린지와 새 활동 상태만 간결하게 표시한다. 상세 화면의 큰 헤더는 스크롤 시 접히게 한다.
3. **알림**: 오늘/이전으로 묶고 읽지 않음은 작은 점과 배경 차이로 표현한다. 알림마다 큰 카드를 반복하지 않는다.
4. **설정**: 계정 설정과 기기 설정을 명확히 나누고 네이티브 그룹 목록 형태로 바꾼다. 현재 상태는 짧은 배지나 보조 문구로 바로 확인하게 한다.
5. **온보딩과 로그인**: 세 화면 이내에서 개인기도, 그룹 공유, 알림의 가치를 실제 화면 미리보기로 설명하고 개인정보 보호를 신뢰 요소로 제시한다.

### P2 — 완성도와 확장성

1. 기도 완료, 저장 성공, 연속 기록 달성에만 180~240ms 정도의 짧은 애니메이션과 햅틱을 사용한다.
2. 최소 터치 영역 44~48px, Dynamic Type, 충분한 명암비, 화면 읽기 라벨, 모션 감소 설정을 지원한다.
3. 태블릿에서는 늘어난 휴대폰 카드가 아니라 NavigationRail과 그룹/기도제목 2열 상세 구조를 사용한다.
4. 캐시된 화면을 즉시 보여주고 새 데이터만 배경 갱신한다. 전체 화면 스피너 대신 최초 로딩 영역에만 스켈레톤을 사용한다.
5. 다크 모드와 새로운 브랜드 색은 화면별로 따로 만들지 않고 동일한 디자인 토큰에서 파생한다.
6. 결제 유도는 홈에 반복 노출하지 않고 사용자가 실제 제한에 도달한 맥락에서 관련 혜택과 함께 제시한다.

## UI 개선 검증 기준

- 홈 진입 후 핵심 행동을 찾는 시간: 3초 이내
- 기도제목 작성과 기도 완료: 각각 두 번 이내의 탭으로 시작 가능
- 홈의 초기 스크롤 길이와 동시에 노출되는 카드 수 감소
- 개인기도/그룹 공유 범위 오인 테스트 0건
- 휴대폰·태블릿에서 텍스트 확대와 한 손 조작 검증
- 전후 스크린샷, 작업 완료 시간, 탭 수를 비교한 뒤 단계별로 적용

## 디자인 판단 기준

1. 사용자가 3초 안에 오늘 무엇을 하면 되는지 알 수 있는가.
2. 기도제목의 개인/그룹 공개 범위를 실수 없이 파악할 수 있는가.
3. 기록과 기도 완료가 한 손으로 두 번 이내의 탭에 가능한가.
4. 연속 기록이 동기를 주되 죄책감이나 과도한 경쟁을 만들지 않는가.
5. 휴대폰, 태블릿, PC에서 같은 기능의 위치와 명칭이 일관적인가.
